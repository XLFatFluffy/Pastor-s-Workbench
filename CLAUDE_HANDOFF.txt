CURRENT VERSION
---------------
0.12.4 — Windows MSI Build Fix + Updater foundation

IMPORTANT CURRENT STATE
-----------------------
Pastor's Workbench started as a local browser application and has evolved into a
pastoral study/workbench application with Bible tools, 1689 Confession, cross references,
research, projects/sermons, a Book Library, and a global Ollama AI overlay.

The project is now being converted into a real Windows desktop application using Tauri 2.
The goal is a standalone Windows application, not something the user must open in
Firefox/Chrome or start with a local web server.

WHAT HAS BEEN BUILT
-------------------
1. Dashboard
   - Functional dashboard with live counts/recent work/quick actions.
   - New sermon/project creation from dashboard.
   - AI quick actions.

2. Bible / 1689 / Cross References
   - Existing Bible/KJV architecture preserved.
   - 1689 Confession integration preserved.
   - Cross-reference integration preserved.
   - Do not replace these with duplicate data stores.

3. Research / Knowledge
   - Research is first-class and reusable across projects.
   - Research can connect to Scripture, 1689 paragraphs, concordance/cross references,
     projects, sermons, lessons, studies, notes, etc.
   - Provenance and distinction between source knowledge and personal conclusions matter.
   - AI-generated research must remain explicitly AI-generated.
   - AI-generated relationships require user approval before becoming accepted knowledge.

4. Expository workflow
   - Expository sermon workflow is already implemented.
   - Study Desk connects Scripture, 1689, cross references, research/notes, and projects.

5. Book Library
   - Users can upload books/source material.
   - Supported source formats include PDF/TXT/Markdown/HTML/JSON text.
   - Books are searchable and passages can be copied.
   - Relevant book context can be supplied to AI.
   - Uploaded books are retrieval/context sources; uploading does NOT train the local model.

6. Global AI
   - AI is a persistent overlay available throughout the application.
   - Separate conversations, like ChatGPT.
   - Conversations can be created and deleted.
   - Conversation history persists locally.
   - AI can receive Workbench context, current-screen context, and book context.
   - AI is intended to become a true assistant integrated into every workspace, not merely
     a standalone chat tab.

7. Local AI
   - Ollama is the primary local AI service.
   - User has Ollama installed.
   - Qwen3 8B is the preferred/recommended model, but the user's machine is resource
     constrained and Qwen3 4B/Gemma 3 can max RAM. User understands they must be mindful
     of RAM usage.
   - Keep model/provider configurable. Do not hard-code a single model permanently.
   - Ollama endpoint is normally http://127.0.0.1:11434.

8. AI settings
   - Model selection.
   - Ollama endpoint.
   - Temperature.
   - System instructions.
   - User/personal AI context.
   - Local/private status.
   - Model detection/connection checking.
   - Qwen3 8B is currently the recommended model.

9. AI chat UI
   - Conversation list with delete functionality.
   - Delete confirmation.
   - Global overlay.
   - Chat area has been through several scrollbar fixes. The latest source contains
     the intended custom scrollbar/flex layout fix, but this area should be tested carefully
     in Firefox/Windows because earlier builds showed a visible-but-nonfunctional scrollbar.
   - Chat composer has bottom spacing intended to avoid the Windows taskbar.

10. Desktop conversion
    - Tauri 2 desktop project has been added.
    - Existing frontend is isolated into a dedicated frontend directory for Tauri.
    - This was required because Tauri rejected frontendDist when it included src-tauri,
      node_modules, and target.
    - Desktop app should run as a standalone Windows app with no normal browser chrome.
    - Native desktop bridge exists for desktop status/app-data/Ollama health concepts.
    - Build helper scripts exist.

11. Desktop build error that was just fixed
    Previous build failed with:
       `icons/icon.ico not found; required for generating a Windows Resource file`
    The current v0.12.3 build adds the required Windows icon and icon configuration.
    Do NOT remove the icon assets/configuration.

12. Updater
    - Updater foundation has been prepared.
    - Tauri updater dependency/configuration has been added.
    - Signing/release endpoint is intentionally NOT fully activated yet.
    - Do not invent or commit a private signing key.
    - A real release endpoint (GitHub Releases is a likely choice) and Tauri signing
      configuration must be established before automatic updates are enabled.
    - Application code and user data must remain separate so updates do not overwrite data.

13. Data
    - User currently stated there is NO existing data that needs migration.
    - Do not claim browser data migration is required.
    - Establish a proper persistent desktop data location before the user starts accumulating

To unblock the user's Windows installation, v0.12.4 uses the Tauri MSI target instead of NSIS.
The updater dependency remains in the project, but automatic updater activation still requires
signed release artifacts/public key and endpoint configuration. Do not remove the updater dependency.


LATEST BUILD ISSUE (v0.12.4)
----------------------------
The user successfully reached the MSI build script, but the script failed with:
  `'tauri' is not recognized as an internal or external command`

Root cause: the package.json declared `@tauri-apps/cli`, but the build batch did not
install npm dependencies before calling the Tauri executable. The Rust/C++ toolchain
was not the problem.

v0.12.6 DESKTOP RUNTIME FIXES
-----------------------------
- User reported that AI, Sermons, Lessons, Research, and other desktop workspaces were not functioning after the first successful installation.
- Root risk identified: browser-side fetch to Ollama from the Tauri WebView can be blocked by CORS/origin differences even though Ollama is running.
- v0.12.6 adds native Tauri commands `ollama_tags` and `ollama_chat` using Rust HTTP so desktop AI does not depend on browser CORS. Browser mode still uses normal fetch.
- v0.12.6 also adds route-error telemetry to the window for easier diagnosis of any workspace module failure.
- Build script now calls `npm run desktop:build` so the package script is the single source of truth.
- Desktop test expectation was corrected to the intentional MSI-only target.
- IMPORTANT: after installing v0.12.6, test AI, Sermons, Lessons, Research, Books, Bible, 1689, Dashboard, Settings, and app restart.
